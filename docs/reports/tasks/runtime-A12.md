Notes for neighbours:
- **Task 13 (`handlers.py`, `processors.py`) — `dispatch_tool` never raises.** It catches `ValueError`/`TypeError` (a model argument that fails a pydantic enum, e.g. `kind="book"`) into `Refused(reason="out_of_scope")` and every other exception (ledger, SMS or database failure) into `Refused(reason="unavailable")`, whose script is `refuse_unavailable` — "please don't count on me for it". A voice handler therefore always has a sentence to speak and must not wrap the call in its own try/except that would substitute different wording. It returns `(None, goodbye_text, True)` for `end_conversation` only; `outcome is None` means "ended", not "failed".
- **Task 13 — band bookkeeping is duplicated on purpose.** `Brain.turn` computes `band` from the outcomes it collected; the plan's voice handler computes the same thing onto `VoiceSession.band` (`3 if item_type.startswith("escalation_") else max(band, 2)`). Voice does not go through `Brain.turn`, so keep the handler's copy; if the rule ever changes, change both. `Captured` is the only outcome that moves the band: a `LinkSent` or a `Refused` leaves the turn at band 1.
- **Task 13 — the rules gate lives in the processor, not in `Brain`.** `Brain.turn` short-circuits before calling the LLM and never speaks the model's text for a gated turn; `RulesGateProcessor` must do the equivalent by intercepting the `TranscriptionFrame` before the user aggregator. Do not call `Brain.turn` from the voice pipeline — it would run a second LLM completion alongside Pipecat's.
- **`ConversationRef` is frozen; `Brain.turn` re-binds a copy locally and does not mutate the caller's ref.** When `health_context_mentioned` fires, the flag is set on a `model_copy` used for that turn's capability calls, and the caller learns about it from `TurnResult.health_context`. The channel service (text-channels plan B2) and `VoiceSession` are responsible for persisting the flag onto their own long-lived ref so it sticks for the *rest* of the conversation, as `data-model.md` requires of `conversations.health_context`. A caller that ignores `TurnResult.health_context` will re-detect the flag every turn from the same sentence but will lose it on later turns that no longer mention the condition.
- **The guard's blocked path files a real item, and that is the point.** When the model claims a completion, the reply becomes `cannot_complete` ("I've passed it to the team and someone will confirm with you …") *and* a `capture_request(kind="question")` item is actually created, so the replacement sentence is true. Any later channel that reuses `Brain` must not suppress that capture; `CLAUDE.md` non-negotiable 1 ("a refusal never claims anything was sent or filed") is satisfied here only because the filing really happens. `guard(..., replacement="")` is deliberate: the model's sentence is dropped entirely rather than softened.
- **Reply assembly order:** free text first, then one rendered sentence per tool call, joined by a single space. When the guard blocks, the `cannot_complete` sentence takes the free-text slot at the front. A turn with neither text nor tool calls yields `reply == ""` — the text channels must decide whether to send nothing or re-prompt; `Brain` does not invent filler.
- **`history` is a list of `{"role", "content"}` dicts and `Brain.turn` appends the new user turn itself** — pass the prior turns only, or the user text is duplicated. `GeminiClient` maps any role that is not `"user"` to `"model"`, so a `staff` message from the human-takeover path (text-channels B5) would be sent as an assistant turn; if that is not what B5 wants, filter or relabel before calling.
- **`FakeLLM` is the test double the whole plan leans on.** It records `(system, history)` pairs in `.calls` — `llm.calls == []` is how `test_rules_gate_short_circuits_without_llm` proves no model ran — and returns `LLMResponse(text="", tool_calls=[])` once its scripted list is exhausted rather than raising, so an over-long scenario degrades to silence instead of an error. It ignores `tools` entirely.
- **`GeminiClient` imports `google.genai` inside `__init__` and `google.genai.types` inside `complete`, not at module scope.** That keeps `import spatalk.brain.driver` free of the SDK for `tests/test_smoke_imports.py` and for any deployment that swaps the vendor. Task 13's `make_llm(settings)` and Task 14's assembly should preserve that: construct the client from settings at call time, never at import time. `thinking_config=ThinkingConfig(thinking_budget=0)` and `automatic_function_calling=AutomaticFunctionCallingConfig(disable=True)` are both load-bearing for voice latency and for keeping tool execution on our side of the boundary — do not drop them when wiring the Pipecat `GoogleLLMService`, which is configured separately through `Service.Settings(...)`.
- **`escalate.reason` reaches `dispatch_tool` from two sources with different vocabularies.** `rules_gate` can only return `human_request | clinical | complaint | payment`; the tool enum also allows `legal | unsure`. Tier C turns any of them into `escalation_<reason>`, and the renderer maps `legal` to the `complaint` script and anything unmapped (`human_request`, `unsure`) to `human_request`. `data-model.md` lists `escalation_unsure` and `escalation_legal` as valid `items.type` values, so nothing further is needed — but a new reason added to the tool enum needs a renderer entry or it silently reads as a human-request callback.
- **Reference-versus-plan check: no disagreement found.** `dispatch_tool`'s argument reading matches `api-surface.md` and `tenant-config.md`; the outcome kinds it produces (`captured`, `link_sent`, `refused`) are exactly the non-`completed`, non-`transferred` members of the enumeration in `data-model.md`; `flows.md` §1 steps 8-9 describe precisely this order (health-context flag, then rules gate short-circuit to a band-3 script with an urgent item, then tool calls rendered from templates). Tier C never constructs `Completed`; `driver.py` imports it only to ask `isinstance(o, Completed)` when deciding whether the guard should let a completion claim through, which is the Tier A path and is confined to `spatalk/brain/tier_c.py` by `tests/test_structural_honesty.py`.
