## What the shape actually is

The notes are drafted from the transcript, grounded against **the caller's own turns only**, then health-scrubbed, then capped at four sentences. That order is the plan's and it matters: a sentence the assistant said but the caller did not — "she chose the Mirapeel facial" — is dropped by `ground` before `scrub_health` ever sees it. A health sentence therefore reaches the fixed line only when it echoes the caller's words, which is the case that matters.

`notes_at` is stamped whenever the drafting ran, including when nothing was stored. That is what makes the job idempotent — the handler skips a conversation that already has `notes_at` — and it keeps `notes` free of placeholder text. A conversation with `notes_at` set and `notes` null means "we drafted and there was nothing worth passing on", which is an honest state and the one the portal must render as no block at all.

## Deviations

- **`runtime/spatalk/ledger/conversations.py` does not exist**; the module is `runtime/spatalk/conversations.py`. `set_notes`, `get_notes` and `queue_call_notes` went there, next to `end_conversation`. Evidence: `ls runtime/spatalk/ledger` -> `__init__.py delivery.py items.py links.py scheduler.py summary.py`.
- **`ConversationOut` does not exist**; the conversation output model has been `ConversationFull` since the portal plan, and it is a schema name the portal's generated `client.ts` already imports (`portal/src/runtime/client.ts:594`). Renaming it would break N2 rather than help it, so the fields went on `ConversationFull` and `ConversationOut = ConversationFull` is an alias in `spatalk/http/internal.py`. **N2 reads `ConversationFull`.**
- **The job's LLM client is `spatalk.text.service.make_text_llm(settings)`, not `voice.pipeline.make_llm`.** `make_llm` returns a Pipecat `GoogleLLMService`/`OpenAILLMService` for the audio pipeline, which is not an `LLMClient` and has no `complete()`. `make_text_llm` reads the identical `LLM_MODEL` vendor switch and returns an `LLMClient`, so the notes still follow the runtime's model wherever it is pointed. The handler prefers `ctx.llm` when the context already carries one (which is what production wires and what the tests inject).
- **Token counts are an estimate.** The `LLMClient` protocol carries no usage counts (voice meters through the Pipecat observer instead), so `usage_events` records `llm_input_tokens`/`llm_output_tokens` at four characters a token, documented as an estimate in `spatalk/ledger/notes.py`. Nothing is recorded at all when the model was never called, which is the no-user-turns case.
- **The cost model was not touched.** Adding the drafting call to `docs/research/rates.json` and `costmodel.py` is not a one-line addition: it is a per-conversation cost inside a per-call-minute model, it needs the same edit in `runtime/spatalk/rates.json` (pinned equal by `tests/test_internal_api.py::test_the_packaged_rates_match_the_researched_table`), and it moves the numbers `check()` compares against the brief's hard ceilings. About 2,000 input and 150 output tokens per conversation on Gemini 2.5 Flash is roughly 0.0004 CAD, so it is small, but it should be added deliberately with the founder's cost review rather than folded into this task.
- **Three existing pins widened, none weakened.** `tests/test_ops_retention.py` asserts the per-tenant count dicts exactly, so both gained `"notes": 0`; `tests/test_qa_gate_c.py::EXPECTED_JOB_KINDS` is a closed list and gained `call_notes` (the test fails on an unlisted kind by design). No assertion was removed or loosened.
- **The morning digest email is unchanged.** The plan's parenthetical says the digest is where notes get read, but `_digest_email` builds one line per item and hands the same `body` string to the WhatsApp digest, so adding notes there would change the WhatsApp text the plan says to leave alone. Scope kept to `build_email` and `build_slack_blocks`, which is what the Interfaces block lists. Worth revisiting if the founder wants notes in the 07:30 digest.
- **`social.handlers.close_and_capture` does not queue the job.** That is the out-of-window Instagram/Messenger path, where the assistant never replied and the whole transcript is one inbound message; drafting notes from it would only paraphrase the message a staff member is already reading. Every conversation that goes through `TextConversationService._finish_turn` (SMS, chat, Instagram, Messenger) does queue it.
- **`_finish_turn` gained a `cfg` first parameter** (`_finish_turn(cfg, conv, turn)`), because the close needs the tenant's `call_notes` switch and the method had no config. Private method, one call site.

## Notes for N2

- Field names in the regenerated contract, exactly:
  - `ItemOut.notes` — `{"anyOf": [{"type": "string"}, {"type": "null"}], "title": "Notes"}`, **in `required`**, so the generated client types it `notes: string | null`, not optional. Present on `GET /internal/tenants/{id}/items`, `GET /internal/conversations/{id}` (both the detail's `items[]`), `POST /internal/items/{id}/acknowledge` and `/resolve`.
  - `ConversationFull.notes` — same shape, in `required`.
  - `ConversationFull.notes_at` — `{"anyOf": [{"type": "string", "format": "date-time"}, {"type": "null"}]}`, in `required`.
  - `ConversationRow` (the list endpoint) carries **neither**, on purpose. `tests/test_call_notes.py::test_the_committed_contract_carries_the_three_new_fields` pins that.
- The label is the tenant's wording, not the portal's. It is `scripts.notes_label` ("AI notes, drafted from the transcript") and reaches the portal through `GET /internal/tenants/{id}/config` (the whole `TenantConfig` JSON) — it is **not** on `ItemOut`. Read it from the tenant settings the portal already fetches; do not hard-code the string.
- Render no block when `notes` is null, and no heading with nothing under it. A card can legitimately have `notes_at` set and `notes` null.
- The notes are prose from a model. Render them as text, never as HTML, and keep the label adjacent so a reader always sees "drafted" before they see the sentences.
- `data-testid="request-notes"` is the plan's, and nothing in the runtime constrains it.
