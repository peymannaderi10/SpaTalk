Notes for neighbours:
- **`render_script`'s `urgent` default is `True`, and that is a trap for scripts that are not urgent.** Every call renders `{confirm_by}` from `BusinessCalendar.due_for("urgent" if urgent else "normal", now)`, so `render_script("cannot_complete", cfg, now)` with the default says "confirm with you **within 15 minutes**" — wrong for a normal-urgency capture. Task 12 (driver) and Task 13 (voice handlers) must pass `urgent=False` for `cannot_complete` and for anything derived from a `normal` item. The default is `True` because the scripts that most need it (`clinical`, `complaint`, `payment`, `human_request`) are all band-3 urgent.
- **Prefer `render(outcome, ...)` over `render_script` for anything that came back from a capability.** `render` uses the outcome's own `confirm_by` (the ledger's real due time) and only `render_script` recomputes a due time from `now`. Rendering a captured item through `render_script("captured", ...)` would quote a time the ledger never stored.
- **`render_script` walks the business calendar even for scripts with no `{confirm_by}`.** With `urgent=False` that reaches `BusinessCalendar.next_open`, which raises `ValueError("no opening hours in the next two weeks")` for a tenant whose `hours` are empty or entirely holiday-covered. Skincentrix is open seven days so nothing hits this today, but a tenant onboarded with placeholder hours would make `render_script("goodbye", cfg, now, urgent=False)` raise. If that ever matters, the fix is to compute `confirm_by` lazily; I did not add it because no test or reference asks for it and it would change the plan's code shape.
- **Placeholders `render`/`render_script` can fill:** `{confirm_by}`, `{service}`, `{url}`, `{name}`, `{phone}`, `{booking_url}`, `{sms_number}`, plus anything passed as `**extra` (extras win). A script containing any *other* `{placeholder}` raises `KeyError` at render time — `spatalk/tenants/schema.py` does not validate placeholder names, so a bad portal edit (Task C3) fails when the sentence is spoken, not when the config is saved. Worth a validator in the portal plan.
- **Task 6's guard must not be pointed at renderer output.** `render(Completed(...), ...)` deliberately contains "booked"/"rescheduled"/"cancelled" (`COMPLETED_TEMPLATE`), and `scripts.link_sent` says "I've just texted you". These sentences are template output, not model output, so they bypass the guard by construction — CLAUDE.md non-negotiable 1 gates *model* utterances. Task 13's `OutputGuardProcessor` sees LLM text frames; rendered outcome wording is spoken with `TTSSpeakFrame` (flows.md §1 step 9) and must stay on that path.
- **`Refused(reason="payment")` renders `scripts.payment`, not a `refuse_payment` script.** There is no `refuse_payment` key in `Scripts` (see `docs/reference/tenant-config.md`), so the payment refusal shares the band-3 payment script and is rendered `urgent=True`. The other four reasons map one-for-one onto `refuse_<reason>`.
- **`Captured(item_type=...)` drives three different sentences:** `send_link` -> `scripts.link_captured` (with `{service}` filled as the literal "the treatment", because `Captured` carries no `service_id`), `escalation_clinical|complaint|payment|legal` -> the matching band-3 script (`legal` shares `complaint`), every other `escalation_*` (including `escalation_human_request` and `escalation_unsure`) -> `scripts.human_request`, and everything else -> `scripts.captured`. Task 8's `PgLedger` must keep using the `items.type` values from `docs/reference/data-model.md`; an unlisted type silently falls through to `scripts.captured`.
