Deviations:
- The roadmap said "the `.env`-export bug fixed in the container entrypoint". In the container Compose injects `.env` already; the bug only exists bare-metal (`spatalk serve` outside Docker, the laptop). Fixed in `serve` itself, which covers both; the scratchpad restart script's `load_dotenv` workaround is now redundant but harmless.
- Found on the way, not in the brief: `KEY=   # note` is read as the note by python-dotenv *and* by Compose; evidence: `dotenv_values` -> `{'EMPTY_WITH_COMMENT': '# a comment'}` and `docker compose run` -> `EMPTY=[# a comment]`. Six such lines sat in the live `runtime/.env` (`TURNSTILE_SITE_KEY`, `TURNSTILE_SECRET_KEY`, `SLACK_BOT_TOKEN`, `GIT_COMMIT`, `INSTAGRAM_APP_SECRET`, `FACEBOOK_APP_SECRET`), the same shape that broke `TELNYX_PUBLIC_KEY` on 2026-09-05; moved by hand, and `serve` now refuses the shape.
- `GIT_COMMIT=` in `.env.example`: first removed, because an `env_file` line overrides the image's ENV even when empty (evidence: in-container `git_commit` was `''` with the line present and `'5e3064a'` without), then restored because `test_qa_gate_c.py::test_every_runtime_setting_is_named_in_the_env_example_and_the_api_surface` and `test_ops_alerts.py::test_the_env_example_names_every_operations_variable` require every setting to be named. The image now also writes the revision beside the installed package (`Dockerfile`, `with_name('GIT_COMMIT')`) and `Settings` falls back to it, so the line is harmless. A first attempt attached the validator to the class from outside, which pydantic ignores (test caught it: `'' == '5e3064a'`); it is a method now.
