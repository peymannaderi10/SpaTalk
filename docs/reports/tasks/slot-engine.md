## Deviations from the spec and the plan

- **The step brief rides at the end of the system prompt, not as a message in the history** (plan Task 7 said "the final instruction in the history"). `GeminiClient.complete` maps every non-user history role to `model`, so a system-role brief would have read as the assistant's own words; the OpenAI client would have kept it. Appending it after the static prompt (after the clock line, which already changes) keeps the cached prefix identical turn to turn. Voice does the same: `voice/steps.py` rewrites the first context message as static prompt + brief (`test_sync_context_puts_the_step_brief_on_the_system_message...` checks the prefix is byte-for-byte unchanged).
- **No `FlowManager`** (spec §6.5, decided before the plan, recorded in its header): Flows would move the system prompt onto the LLM service's settings, away from the context where the gate, the guard and `_finalize` read it. The voice adapter syncs the step by hand: `LLMContext.set_messages` for the brief, `LLMContext.set_tools` for the step's tools, `TTSSpeakFrame` for the fixed lines; the guard re-asks the open question after a model turn with no tool call (`FunctionCallInProgressFrame` marks a turn that had one).
- **The record files itself when the last required slot lands** (plan header). `file_request` is still offered at `COMPLETE` and works, but the engine does not wait for the model to call it; on a call with an SMS number a booking asks the route question first. Tests: `test_the_record_files_itself_when_the_last_slot_lands`, the nine-message chat walk in `test_widget.py`.
- **The caller id is the number to confirm** on every channel (`open_flow` puts it in `Slots.phone` unconfirmed; SMS confirms it by itself); a withheld caller id is asked for outright (`ask_phone`). The plan had the voice-only `ask_phone_same` decided from the channel; the record is the better source.
- **A booking on a text channel ends with the link in the conversation** (SMS, chat, Instagram, Messenger), as Task B4 always did, instead of filing; on a call the route question decides, and a call without an SMS number files a callback. Spec §4.1 step 9 named only the call.
- **The offers question and the treatment question are one question for a new client**: after `ask_offers` the SERVICE step asks `ask_after_offers` ("What did you have in mind?") rather than `ask_service`, so the caller is not asked twice in one breath; and the model's recital of the offers (or of two or three options) is kept whole rather than trimmed to one acknowledgement sentence (`Applied.model_speaks`).
- **`training_enquiry` is a request kind** (start_request, `ITEM_TYPE`): the old `CaptureKind` had it, the spec's list did not; the promptfoo suite and `TYPE_LABELS` needed it.
- **`choose_window.date` stays a free string** on the tool: it is closed by `PreferredWindow`'s validator (an ISO date, a weekday or "any"), exactly as before; the structural-honesty tests name it as the one allowed non-transient string.
- **The clinical gate's dead-ledger test moved to the emergency path** (`test_ledger_failure_on_the_voice_gate_refuses_instead_of_promising_a_callback`): a clinical match no longer writes at the gate, so the refusal can only be provoked where a write happens.
- **`test_scenarios_provider`'s synthetic clinical output** still passes `band3_gate` because the grader accepts either an urgent item (emergency, human request) or the clinical flow opened on the record.
- **Tests rewritten rather than deleted**: `test_lead_context.py` and `test_lead_context_verification.py` lost the seven and six tests that asserted lead fields on the removed tool parameters and prose bullets; each has an engine counterpart asserting the same invariant on the record, the draft or the tools (no tool carries `returning_client`/`practitioner`/`concern`; the draft's values are closed; the concern is never typed by the model). `test_call_notes.py` lost three prompt-bullet tests and gained three against the scripts and the order. The five QA-gate cases that filed through the old tools now seed a filled record and file through the engine; the "link with no caller id" case asks for a number instead of refusing.
- **`ec952dd`** fixes a red test that predates the branch (`test_the_packaged_rates_match_the_researched_table`): the afternoon's rate-file change updated `docs/research/rates.json` but not the packaged copy at `spatalk/rates.json`.
