## Deviations

- **There is no takeover to restyle.** The task's map asks for "the takeover and block actions" in the transcript. `grep -rni "takeover" portal/src portal/e2e-tests` returns nothing: the portal has never had one — takeover lives in the runtime (`spatalk/text/takeover.py`) and reaches the team through Slack. Adding an operation is not this task's, so the sheet carries the block action only, and `controller` (the field takeover writes) is shown as a column and offered as the **Handled by** facet, which is what answers "needs a human".
- **No "last message" column on the conversations list.** `ConversationRow` does not carry one, and reading a message would be an audited transcript read per row. Length and Requests stay, as they were.
- **The conversations table pages the runtime's way.** `getTenantConversations` filters by *one* channel and *one* band and pages at 25, so the table is on `manualPagination` with the runtime's page as the page and `rowCount` from its total. A facet naming a single value is asked of the runtime; a facet with several values chosen, and the toolbar's search on the caller, narrow the page that came back — the runtime has no search to ask for. Sorting is off on every column for the same reason: sorting one page of a list the server ordered would read as sorting the list.
- **`DataTablePagination` gained an optional `pageSizeOptions`** (R0's file). Without it the size select offers 10 to 50, and on a manually paged table every one of those but the runtime's own is a size nobody can honour.
- **Two chart placeholders, both in the shape of the kit's `Overview` component.** `UsageOverview` in `OverviewPage.tsx` draws the window's totals per channel and names the busiest day; `RevenueAndProfitChart.tsx` draws the seven days it was given as proportional bars. Neither imports ApexCharts any more, and neither promises a picture that is not there. **R3 replaces the body of each with the shadcn chart components.**
- **Three Playwright specs were edited, each for an interaction pattern that no longer exists**, which is the only edit the plan's file list permits:
  - `client.spec.ts`, "narrows the list to one channel": the two `select` elements are the kit's faceted filters, so it opens the Channel popover, picks Text, and clears with `table-reset-filters`.
  - `client.spec.ts`, the requests tabs: Open and Resolved are the kit's tabs, so `getByRole("button")` became `getByRole("tab")` in three places.
  - `orgs.spec.ts`, the invitation: the form is the kit's dialog and the role a Radix select, so it opens the dialog and picks the role from it.
  What each test proves is unchanged.
- **The settings side navigation is buttons, not the kit's router links.** The kit's eight settings tabs are eight routes; ours are one route with a `?tab=`, and four specs reach the sections as buttons (`client.spec.ts` twice, `integrations.spec.ts`, `sms-blocks.spec.ts`, `shell.spec.ts`). They wear `buttonVariants({ variant: "ghost" })` exactly as the kit styles its links.
- **The save button sits in the section header.** The kit's forms each carry their own submit; this tenant's configuration is saved whole, once, whichever section is open, so `ContentSection` grew an `actions` slot the kit's has not got.
- **`SchemaInput` carries a `__unset__` sentinel** between a nullable enum's select and the draft, because Radix will not take an empty string as a value. It never reaches the runtime.
- **`DropdownEditDelete.tsx` is deleted.** Its Edit and Delete items had no handler and did nothing; a control that claims an action it does not take is what non-negotiable 1 forbids. `admin/layout/Breadcrumb.tsx` and `admin/layout/LoadingSpinner.tsx` went with it — the shell has carried breadcrumbs since R1 and nothing imported either.
- **The kit's column-header dropdown is not used on the tenants table.** `admin.spec.ts` clicks `sort-name` twice and reads the order, so the headers stay toggling buttons, styled as the kit's ghost header buttons with its arrow icons. The sort itself is still `sortTenantRows`, which `agency.test.ts` covers.
- **The auth card's title wraps an `h2`.** The registry's `CardTitle` is a `div`, and the suite reads the invitation page by its heading.
- **A fourth commit.** `6d1546f` corrects two things in the first commit's layout: the conversations list is no longer `fixed` (the kit's table page is not, and fixed it would have clipped a full page of rows with no scroll of its own), and `OrgShell`'s column clips its own overflow when a page asks for `fixed`, which is what lets the requests grid and the settings section scroll inside the shell.
- **`src/user/AccountPage.tsx` is untouched.** It is not in the task's map and already sits on the registry's card and separator.
- **The marketing landing page and the privacy page were left**, as the task says. So were `NavBar.tsx`, `DarkModeSwitcher.tsx` and `PricingPage.tsx`, which only render outside the shell.
- **Prettier was not run**, following R0 and R1: no config file, no format script, no CI step.
- **`wasp build`, `wasp start`, `wasp test`, `wasp db` and `wasp compile` were not run.** Types were checked with `tsc` emitting to `/tmp`, the stylesheet with the standalone Tailwind v4 CLI, the tests with Vitest through WSL node.
