- The running `wasp start` did not regenerate the SDK for the new action (`.wasp/out/sdk/wasp/server/operations/actions/index.ts` still dated 2026-09-03 after the edit; `tsc` -> "no exported member 'UpdateOrganizationBranding'"). `wasp compile` under Node 24.20.0 — the same compile step `wasp db migrate-dev` had already run once this session — regenerated it; not a restart, and the dev server kept running. Wasp's npm install also added `nodemailer` to the generated server workspace's entry in `portal/package-lock.json`; that is Wasp's, not this task's, and was restored with `git checkout` rather than committed.
- The operation lives in `portal/src/client/operations.ts` as the brief says, beside `saveTenantConfig`, and copies its gate: `ownerSession` (owner + subscription), so a lapsed clinic cannot re-brand what it cannot open. The brief's name `updateTenantConfig` does not exist; `saveTenantConfig` is the save it meant.
- Added, not in the brief: the JSON body limit. Wasp's global middleware is `express.json()` at Express's default 100 KB (`.wasp/out/server/src/middleware/globalMiddleware.ts`), and a 200 KB logo is a ~273 KB base64 string inside the operation's JSON, so every upload over ~73 KB would have died with a 413 before reaching `validateBranding`. `portalMiddleware` now sets `express.json({ limit: JSON_BODY_LIMIT })` in place of Wasp's entry (same key, same position); `security.server.test.ts` drives the real parser with a 280 KB body through a `Readable` and asserts it parses. This is the one runtime import `security.ts` now makes (Express itself); its header says so.
- `validateBranding` is a pure function in `portal/src/organizations/branding.ts` rather than a test of the operation itself: the server tests (`*.server.test.ts`) mock `wasp/server` and drive plain functions, and `src/client/operations.ts` also imports `wasp/server/operations` and the runtime client, so the operation is only the owner check, the call and the write. The test caught one real gap on its first run: `data:image/png,rawbytes` (no `;base64`) was reported as the wrong type because the MIME was cut at a `;` that was not there; the type now runs to the first `;` or `,`. Fixed before the commit, inside the same task.
- `TenantMark` shows a logo with `object-contain` instead of `object-cover` (one word): a wordmark wider than it is tall was being cropped to the square, which would have made the feature's own preview wrong. `tenant-mark.test.tsx` asserts nothing about the fit and is unchanged.
- Dark mode is read from the body's `.dark` class with a `MutationObserver` (`useDarkClass` inside `useBrandingStyle`) rather than from a second `useColorMode()` in the shell: `useColorMode` is `useLocalStorage`, whose state is per hook instance, so a copy in `AppLayout` would not have followed the `DarkModeSwitcher`'s toggle until a remount. `AppLayout.test.tsx` toggles the class and asserts the tokens follow.
- The "Saved" notice is the `Alert` the other tabs use (`data-testid="branding-saved"`), not a toast: nothing in `src` calls `toast()` (`grep -rn "useToast\|toast(" src` outside the hook and the ui component -> no matches), so the Alert is what "like the other tabs" means here.
- `SettingsPage` hides its own "Save settings" button, the "Saved as version n" notice, the field-error list and the config `Problem` while the Branding section is open (`configuration = tab !== "Branding"`), since none of them are about branding and the config save button on that tab would have written a settings version a person did not ask for.

Notes for neighbours:
- The portal must be restarted for the Branding tab, the action and the new body limit to be live; the migration is already applied and the SDK regenerated, so a restart is all it needs.
- Branding is not tenant configuration. It is read through `getOrganization` (`OrgShell.Org`), written by `updateOrganizationBranding`, and never enters the settings draft, `saveTenantConfig`, or a config version. `listMyOrganizations` deliberately does not carry the logo, so the switcher's list stays small; the shell hands the current organisation's logo to `OrgSwitcher` as `logoUrl`.
- After a save, Wasp invalidates `getOrganization` (the action declares `Organization`), so the shell re-themes and the sidebar mark updates without a reload; the tab's own effect resets its draft from the refreshed organisation.
- The tokens go inline on the shell's root (`data-slot="sidebar-wrapper"`). Anything Radix portals to `body` — dropdown menus, selects, dialogs, the toaster — sits outside it and keeps the kit's default colours. To brand those too, set the same tokens on `document.documentElement` from `useBrandingStyle`; not done here because the brief asked for the shell's root and the admin shell must stay untouched.
- Adding a preset: one entry in `THEME_PRESETS` with every `CSS_VARS` token for both modes; `themes.test.ts` fails on a missing token, and `validateBranding` accepts the id from `THEME_PRESET_IDS` with no other change. Changing the kit's `Main.css` palette requires the same change to `clinic`, which the test enforces.
